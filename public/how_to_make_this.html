第 1 页｜准备与检查

先让 Codex 看清楚环境

你现在做

  • 打开 Codex 并进入项目工作区。
  • 准备代码模型会话。
  • 如果要生图，准备图片 API/base URL。
  • 如果要部署，准备 Cloudflare 账号（可后置）。
  • 不要把 API key 写进代码或文档。

复制这段提示词

我想做一个可以在浏览器运行的《三国杀》风格单机网页游戏。

请先不要写代码，做只读检查：
1. 查看工作区、已有项目和技术栈；
2. 查看 package.json、AGENTS.md、测试脚本；
3. 检查当前会话可用的工具、图片模型和浏览器工具；
4. 判断新建项目还是继续修改；
5. 输出首版范围、目录、顺序和验收标准。
预期结果：Codex 会先报告现状和计划，而不是盲目开工。
第 2 页｜范围与骨架

先定一个能完成的首版

首版不做

请把项目首版限定为玩家 1v3 AI 的单机身份局。
先创建 Vite + React + TypeScript 骨架。
规则必须与 React UI 解耦：玩家点击和 AI 行动调用同一套状态转换。
请输出文件树，并先不要堆视觉细节。

第 3 页｜最小可玩闭环

先实现一局能玩的游戏

现在实现最小可玩闭环：
1. 定义 GameState、PlayerState、Card、Hero、Identity、TurnPhase、GameEvent；
2. 实现身份、体力、手牌、牌堆、弃牌堆和当前行动者；
3. 实现摸牌、出牌、弃牌、结束回合；
4. 实现【杀】【闪】【桃】【酒】、伤害、濒死、阵亡；
5. 实现主公/忠臣/反贼/内奸的基础胜负；
6. 加一个不会出非法牌的简单 AI；
7. 为以上规则写 Vitest 测试；
8. 完成后运行测试并汇总结果。

成功标准

  • 可以开始一局
  • 可以出牌和响应
  • 可以结束回合
  • 可以结算胜负

不要急着做

先别加入复杂装备、几十种锦囊和华丽特效。没有稳定状态机，后面会反复重写。

第 4 页｜让规则能被点击

把状态机接到 React 牌桌

请把当前规则接到 React 牌桌 UI：
1. 开局页选择武将、身份、音效；
2. 对局页显示 AI、中央牌桌、玩家手牌、日志和结束回合；
3. 点击手牌后高亮合法目标，非法目标显示原因；
4. 响应窗口明确提示需要【闪】、【杀】、【桃】或【无懈可击】；
5. 加入重开、取消选择和结算面板；
6. 启动开发服务器并返回 localhost 地址。

先实现可操作性，再做华丽动画。
你亲手检查：开始一局 → 点手牌 → 选目标 → 结束回合 → 处理 AI 响应。

第 5 页｜生图与牌面

有模型就生成，没有就先兜底

先核验能力

请确认当前会话是否暴露 image_gen。
如果没有，请检查模型列表、base URL 和环境变量。
不要打印真实 API key。
不可用时先用原创 SVG/纹理完成项目。

第一次不可用不是失败；先保证页面可运行，未来替换资源。

第 6 页｜规则迭代

每次“继续”只解决一组问题

继续规则审计。本轮只检查：
1. 座位距离与【杀】【顺手牵羊】目标；
2. 群体锦囊逐个响应；
3. 【决斗】双方交替出【杀】；
4. 【无懈可击】多层响应保留原牌和目标。

每项先写回归测试，再改实现。
完成后运行全部测试和生产构建。

下一轮示例

负体力、每张桃回复 1 点、濒死者优先自救、酒自救、连环逐人结算。

再下一轮

藤甲、白银狮子、雌雄双股剑、装备区和判定区可见性。

原则

发现 → 测试 → 修复 → 重跑；不要一次修改十个机制。

“继续”的正确写法：带优先级、范围和验证命令，而不是只发两个字。
第 7 页｜体验升级

把“太快、不清晰、没质感”量化

请按以下验收要求修改表现层：
1. AI 每个动作间隔约 3 秒，一次只执行一个动作；
2. 文案显示“谁 → 对谁 → 使用什么牌”；
3. 目标角色高亮，牌面从来源飞向目标；
4. 出牌、响应、命中/闪避、治疗、技能、阵亡进入事件队列；
5. 每条事件约 0.85 秒依次播放；
6. Playwright 检查时序、文案、目标高亮和 pageerror。
期望看到：关羽 → 张飞 ·【杀】，而不是只有“出了杀”。
请用 EdgeTTS 生成武将出杀、闪避、技能、受伤、濒死、阵亡、胜利台词；
保存到 public/audio/voices；
失败时回退 speechSynthesis。

第 9 页｜Cloudflare 部署

让 Codex 部署到免费 Cloudflare

本地验证通过后，请部署到 Cloudflare 免费方案：
1. 检查 package.json、构建命令和 dist；
2. 判断 Pages 或 Wrangler；
3. 先告诉我登录、项目名、构建命令和输出目录；
4. 不要打印或提交 API key、token、密码；
5. 执行部署并返回公开 URL；
6. 用 curl 和浏览器检查首页、JS、CSS、PNG、MP3；
7. 若需要我登录或配置 DNS，只明确告诉我那一步。

目标：免费静态前端，无服务器数据库。

线上检查

curl -I https://你的域名
curl -I https://你的域名/assets/card-sha-gpt2.png

不要误判

命令退出码为 0 不等于用户能访问。必须打开公开 URL，开始一局并检查关键资源。

第 10 页｜总提示词与验收

复制这条总指令，然后按页执行

请在当前工作区从零制作一个三国杀风格单机 1v3 网页游戏。
使用 Vite + React + TypeScript，规则状态机与 React UI 解耦；
玩家可选武将和身份，AI 自动补齐；

1. 先检查工作区和工具，输出计划；

3. 每轮只解决一组问题；
4. 每轮补回归测试并运行构建/烟测；
5. 工具不可用时给出可运行兜底；
6. 最终返回地址、文件、测试、线上检查和已知边界。

现在先检查，不要直接写代码。

最终五行交付格式

访问地址｜本轮完成｜主要文件｜验证结果｜已知边界

完成标准

  • 能开始、出牌、响应、结算

  • 桌面/窄屏无溢出
